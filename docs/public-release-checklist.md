# GitHub 공개 전환 체크리스트

이 문서는 로컬 준비 상태를 기록합니다. 체크 항목을 완료하기 전에는 저장소 공개 전환, 푸시 또는 릴리스를 진행하지 않습니다.

## 공개 전 필수 결정

- [ ] **소스 코드 라이선스 선택:** 간단한 재사용 허용은 MIT, 명시적인 특허 허여가 필요하면 Apache-2.0을 검토합니다. 라이선스를 추가하지 않으면 기본 저작권이 적용되어 다른 사람이 코드를 보더라도 일반적인 복제·수정·배포 권한은 얻지 못합니다. 선택 전에는 `LICENSE`를 임의로 만들지 않습니다.
- [ ] **서울 경계 데이터 출처 확인:** `data-src/seoul-boundary.geojson`, `public/data/seoul/boundary.json`, `src/data/seoulBoundary.ts`의 원본 URL, 취득일, 라이선스와 재배포 조건을 확인합니다. 확인할 수 없으면 출처가 명확한 데이터로 교체합니다.
- [ ] **Git 이력의 개인정보 결정:** 현재 두 커밋의 작성자 이메일은 GitHub noreply 형식이 아니며, 과거 파일 blob에는 개인 로컬 절대 경로가 남아 있습니다. 현재 파일에서 지워도 공개 이력에서 복원할 수 있으므로 노출을 수용할지, 공개 전에 이력을 다시 작성할지 결정합니다. 실제 값은 문서에 기록하지 않습니다.
- [ ] **보안 보고서 공개 범위 결정:** `docs/security/`의 공격 경로와 아직 남은 endpoint connector 위험을 공개해도 되는지 검토합니다. 미해결 문제가 실제로 악용 가능하면 수정하거나 공개 시점을 조정합니다.

위 라이선스 선택 기준은 일반적인 준비 메모이며 법률 자문이 아닙니다.

## 저장소 점검

- [x] 현재 작업 트리의 개인 로컬 절대 경로를 프로젝트 개요에서 제거했습니다. 과거 이력은 위 필수 결정 항목에 남겨 두었습니다.
- [x] `.env`, 개인 키, 모바일 서명 파일과 빌드 산출물을 `.gitignore`에 추가했습니다.
- [x] `SECURITY.md`, `CONTRIBUTING.md`, 데이터 라이선스 안내 초안을 추가했습니다.
- [ ] 현재 파일과 전체 Git 이력에 비밀정보가 없는지 공개 직전에 다시 검사합니다. 발견된 실제 키는 삭제만 하지 말고 폐기·재발급합니다.
- [ ] `npm audit`의 알려진 개발 도구 체인 경고를 공식 앱인토스 프레임워크 최신 버전과 다시 비교합니다.
- [ ] PR 2·PR 3 변경을 의도한 커밋으로 정리하고 전체 테스트·타입 검사·린트·빌드를 다시 통과시킵니다.
- [ ] `package.json`의 `"private": true`는 유지합니다. 이는 npm 오배포 방지 설정이며 GitHub 저장소 공개 여부와 무관합니다.

## 데이터와 저장소 크기

- [x] OSM 기반 경로·장소·건물 데이터에 저작자 표시와 ODbL 링크를 추가했습니다.
- [ ] 다음 데이터 갱신부터 `OSM_SOURCE_URL`과 `OSM_DOWNLOADED_AT`을 지정해 원본 다운로드 URL·취득 시각을 manifest에 남깁니다. PR 3은 원본 파일명·크기·수정 시각·SHA-256과 생성기 버전을 자동 기록합니다.
- [ ] 현재 `public/data`는 약 66MB이고 서울 타일만 약 56MB입니다. Git에 계속 둘지, 향후 릴리스 자산이나 별도 저장소로 옮길지 결정합니다.

## GitHub에서 공개 직후 할 일

- [ ] Private vulnerability reporting을 활성화하고 `SECURITY.md`의 안내가 실제 화면과 일치하는지 확인합니다.
- [ ] 기본 브랜치 보호, Dependabot alerts, secret scanning과 CodeQL 적용 여부를 확인합니다.
- [ ] 저장소 설명, 주제 태그, 대표 이미지와 앱 화면을 추가합니다.
- [ ] 공개된 파일 목록과 커밋 이력을 로그아웃 상태에서 다시 확인합니다.
