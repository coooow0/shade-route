처리한 발견 사항

Medium

DSC-003 · 고차수 인접 배열

경로: 오염된 타일의 star 그래프 → 배열 spread 반복 → WebView CPU·메모리 고갈.

수정: 선형 인접 구조, 노드 차수 64 상한. 정상 실측 최대는 11.

Medium

DSC-004 · 연결 요소 재스캔

경로: 수많은 분리 way → 요소마다 전체 간선 필터 → O(C×E).

수정: BFS 중 간선 ID를 수집하고 512개 요소를 상한으로 설정.

Medium

DSC-005 · Leaflet 레이어

경로: N개 세그먼트 → casing·color 2N 레이어 생성.

수정: multi-polyline을 casing·connector·shade·sunny로 묶어 최대 4회만 생성, 경로 2,000 세그먼트 상한.

Low

DSC-006 · 숨겨진 길안내 DOM

경로: 접혀도 전체 <li> mount + 항목별 findIndex.

수정: 펼칠 때만 mount, index 직접 사용, 400단계 초과 표시 거부.

Medium

DSC-011 · compact 좌표 확장

경로: 긴 숫자 배열 → 대량의 {lat, lon} 객체 확장.

수정: way·building·tile·route 단위 예산을 compact 상태에서 먼저 검증.

Low

DSC-012 · legacy schema 1

경로: 확장된 legacy 객체가 compact 예산 검사를 우회.

수정: 루트 타일은 schema 2만 허용. 현재 타일 812개 모두 호환.

Medium

DSC-031 · 겹친 그늘 후보

경로: 한 지점에 많은 hull을 겹침 → 샘플마다 모든 다각형 검사.

수정: 지점당 RBush 후보 512개 상한.

Low

DSC-037 · 서울 경계 전체 스캔

경로: 장소 후보마다 약 1,495개 경계 간선을 반복 스캔.

수정: bounding box + 128개 위도 버킷. 2,304개 격자 좌표가 전체 스캔 참조와 동일.

심각도 보정

자원 고갈 영향은 재현되지만, 핵심 데이터는 same-origin 정적 아티팩트입니다. 외부 공격자는 배포·캐시·CDN·생성 파이프라인 오염이 필요하므로 Critical/High로 분류하지 않았습니다.

오류 처리와 테스트

사용자 안내

ROUTE_DATA_TOO_COMPLEX를 내부 상세 노출 없이 “이 지역의 경로 데이터가 너무 복잡해요”로 바꿔 표시합니다. 결정적 실패에 무한 재시도 버튼은 두지 않습니다.

핵심 보안 회귀 검증: 9개 파일, 64개 테스트 통과. 전체 품질 게이트: 29개 파일, 170개 테스트 통과. 커버리지는 문장 87.47%, 분기 82.86%, 함수 92.76%, 라인 91.53%입니다. TypeScript·ESLint·앱인토스 AIT 빌드도 모두 통과했습니다.

후속 성능 항목

minified 웹 JavaScript가 약 1.47MB로 500kB 권장 크기를 넘는 빌드 경고가 남아 있습니다. 실기기 초기 로드 측정 후 코드 분할을 검토할 항목입니다.
