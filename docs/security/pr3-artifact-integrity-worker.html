manifest에도 같은 해시 기록

manifest와 타일만 함께 바꾸는 변조를 막으려면 신뢰 시작점이 mutable manifest 밖에 있어야 한다. PR 3은 그 시작점을 배포 JS 번들에 둔다. places는 번들 root와 manifest 모두에 같은 해시로 기록한다. public 경계와 런타임 TypeScript 경계는 한 생성 실행으로 만들고 drift를 빌드 전에 검사한다.

같은 경로 알고리즘을 쓰므로 총 계산 시간 감소를 주장하지 않는다. 확인한 개선은 메인 스레드 분리와 작업 취소다. Worker 종료는 실행 컨텍스트를 끝내지만, 실기기 네트워크 계층이 이미 시작한 전송을 즉시 해제하는지는 보장하지 않는다.

기준은 main의 010e6e3 위에 있는 커밋 전 PR 2·PR 3 로컬 변경이다. 아직 immutable commit SHA가 없어 이 상태를 문서만으로 정확히 재현할 수는 없다.

남은 위험

  • 로컬 빌드는 통과했지만 앱인토스 iOS/Android 실기기의 Worker + crypto.subtle 호환성을 확인해야 한다.
  • 실기기 경로 지연·프레임과 Worker 종료 뒤 네트워크 자원 해제 시점은 아직 측정하지 않았다.
  • 스테일 캐시는 잘못된 경로 대신 fail-closed 오류를 만든다. immutable release URL과 캐시 교체 정책은 후속 운영 개선이다.
  • integrity root는 JS 번들을 신뢰한다. JS와 데이터를 함께 교체하는 공격은 플랫폼 아티팩트 서명이 막아야 한다.
  • 현재 원본의 다운로드 URL·취득 시각은 확인할 수 없어 provenance에 빈칸으로 남았다. 다음 데이터 갱신부터 필수로 기록한다.
  • CSP 헤더와 worker-src 'self'는 호스팅 계층 확인 후 별도로 적용한다.
  • PR 2의 endpoint connector 제한 geometry·출입구 접근 정책은 후속 보안 작업이다.
