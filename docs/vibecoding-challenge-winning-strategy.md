# 그늘길 바이브코딩 챌린지 수상 전략

> 작성일: 2026-08-01  
> 최근 갱신: 2026-08-02  
> 대상: 2026년 7월 앱인토스 바이브코딩 챌린지 `미니앱과 함께하는 여름`

## 결론

그늘길은 여름 테마 적합성과 아이디어 차별성이 강해 수상권에 도전할 만하다. 그러나 현재 구조는 기술적 완성도에 비해 서울 사용자 유입, 첫 결과 전환, 재방문이 약하다. 7월 챌린지의 1차 심사는 단일 지표가 아닌 지표 종합 평가이므로, 8월 심사 기간에는 이 세 흐름을 함께 개선해야 한다.

P0는 다음 순서로 진행한다.

1. 콘솔에서 스마트 발송의 횟수·주기, 랜딩 경로, 서울 사용자 타기팅 가능 여부를 확인한다.
2. 경로 결과 요약 문장과 `route_result_view` 계측을 현재 출시 수정사항과 한 번들로 만든다.
3. 헤드리스 전체 검증과 320px·390px·샌드박스 화면 확인을 모두 통과한 번들만 한 번 배포한다.
4. 라이브 이벤트 수집을 확인한 뒤 `route_result_view`를 대표 전환 지표로 설정한다.

## 조사 범위와 한계

5월 수상작은 앱인토스 개발자 커뮤니티의 공식 발표에서 확인했다. 6월 수상작은 2026년 7월 30일 앱인토스 콘솔에 게시된 공식 공지에서 확인했다. 콘솔 공지 주소에는 워크스페이스와 미니앱 식별자가 들어 있어 공개 저장소 문서에는 주소를 기록하지 않았다.

6월 작품 중 `찰칵시루`는 공개 서비스 소개에서 기능을 확인했다. 나머지 작품은 공식 수상작 이름만 확인했으며, 세부 기능은 이름으로 단정하지 않았다.

## 이전 챌린지에서 확인한 심사 방향

### 5월: 귀여운 게 최고야

5월 챌린지는 리텐션, MAU, 테마 적합성을 종합 평가했다. 최종 수상작은 다음 8개다.

| 순위 | 수상작 |
| --- | --- |
| 1등 | 흠 |
| 2등 | 버니타임:집중타이머, 엄마 밥 줘 |
| 3등 | 럼버캣 : 고양이 나무꾼, 마이펫 팡팡, 매치 웨이브 3D, 날씨 공룡, 졸린 돌멩이 |

공식 발표로 수상작 이름과 순위는 확인했지만, 신뢰할 만한 1차 자료가 없는 작품의 세부 기능은 단정하지 않는다. `졸린 돌멩이`는 제작자 공개 글에서 귀여움에 집중한 작은 앱으로 소개됐다. [제작자 공개 글](https://story.seonggoos.com/nomad-worker-in-danang/)

공식 심사 기준, 작품 이름, 확인 가능한 제작자 설명의 범위에서는 다음 시사점을 얻을 수 있다.

1. 여러 수상작은 앱 이름만으로 주제나 용도를 짐작할 수 있다.
2. 최종 심사에 사용자 경험이 포함되므로, 설명을 읽지 않아도 첫 행동을 시작할 수 있게 설계해야 한다.
3. 타이머나 날씨처럼 반복 사용을 연상시키는 작품이 포함됐다. 실제 리텐션 효과는 공개 자료만으로 확인할 수 없다.
4. 범위가 작더라도 주제와 감정을 일관되게 표현한다.

### 6월: 일상이 편해지는 순간

6월 챌린지는 7월 1일부터 26일까지의 활성 사용자 수(AU)로 1차 심사를 진행했다. 1차 통과작은 완성도, 테마 적합성, 사용자 경험으로 최종 평가했다.

공식 수상작은 다음 8개다.

| 순위 | 수상작 |
| --- | --- |
| 1등 | 찰칵시루 |
| 2등 | 택배 가격비교, 지금환전하개? |
| 3등 | 밤마실, 근처쿠폰, 혈압·혈당 건강수첩, 내일 주가 미리보기, 할인 정보 |

`찰칵시루`는 소상공인이 사진 한 장으로 약 3분 안에 AI 카드뉴스를 만드는 서비스다. 공개 소개 화면은 사용자를 `소상공인`으로 좁히고, `사진 한 장`, `3분`, `업종 선택 → 사진 업로드 → 완성`처럼 입력과 결과를 구체적으로 설명한다. [찰칵시루 공개 서비스 소개](https://www.snapsiru.com/)

나머지 수상작은 공개 자료만으로 세부 기능을 검증하지 못했다. 다만 공식 앱 이름 자체에서 해결하려는 생활 문제는 분명하게 드러난다.

- `택배 가격비교`: 택배를 보내기 전 가격 비교
- `지금환전하개?`: 환전 시점을 판단할 때 필요한 정보
- `근처쿠폰`: 주변에서 사용할 수 있는 쿠폰 탐색
- `혈압·혈당 건강수첩`: 반복 측정값 기록과 확인
- `내일 주가 미리보기`: 다음 거래일을 앞둔 정보 확인
- `할인 정보`: 구매 전 할인 정보 탐색

위 설명은 앱 이름에서 확인되는 문제 영역을 정리한 것이며, 실제 세부 기능을 뜻하지 않는다. `밤마실`은 이름만으로 기능 범위를 판단하지 않았다.

6월 결과에서 다음 패턴을 찾을 수 있다.

1. 사용자가 겪는 문제를 앱 이름만으로 이해할 수 있다.
2. 비교, 조회, 기록, 생성처럼 완료 기준이 분명한 행동을 제공한다.
3. 택배 발송, 환전, 건강 측정, 투자 확인, 할인 탐색처럼 반복해서 생기는 순간을 잡는다.
4. 1등은 넓은 생활 편의보다 특정 사용자와 결과를 구체적으로 약속한다.

이 기준은 기능 수보다 다음 항목이 중요하다는 뜻이다.

- 많은 사용자가 부담 없이 시작할 수 있는가
- 핵심 기능이 실제로 끝까지 동작하는가
- 결과를 보기까지 실패하거나 이탈하는 구간이 적은가
- 작은 불편을 명확하게 해결하는가

그늘길에도 같은 기준을 적용할 수 있다. `그늘길`이라는 이름은 문제를 잘 설명하지만, 결과 화면은 아직 `몇 분 더 걷고 예상 햇빛 노출이 몇 분 적은지`를 한 문장으로 약속하지 않는다. `찰칵시루`의 `사진 한 장, 3분 완성`처럼 그늘길도 `빠른길보다 2분 더 걷고 예상 햇빛 노출 8분 감소`를 핵심 결과로 앞세워야 한다.

### 7월: 미니앱과 함께하는 여름

7월 챌린지는 8월 1일부터 26일까지의 지표를 종합해 1차 심사를 진행한다. 최종 심사는 완성도, 테마 적합성, 사용자 경험을 평가한다.

그늘길은 공식 주제 가이드 중 `무더위를 시원하게 보낼 수 있도록 도와주는 앱`에 직접 해당한다. 주제 적합성을 위해 기능을 억지로 추가할 필요는 없다. 지금 필요한 것은 핵심 기능을 더 많은 사용자가 성공적으로 경험하도록 만드는 일이다.

## 그늘길의 현재 경쟁력

| 평가 항목 | 현재 판단 | 근거 |
| --- | --- | --- |
| 여름 테마 적합성 | 매우 강함 | 한여름 보행 중 햇빛 노출을 줄인다. |
| 아이디어 차별성 | 매우 강함 | 출발 시각의 건물 그림자를 계산해 세 경로를 비교한다. |
| 기술적 완성도 | 강함 | 서울 보행 데이터, 그림자 계산, 세 경로 비교, 현재 위치, 상세 안내를 제공한다. |
| 첫 사용 이해도 | 보통 | 첫 화면은 기능을 설명하지만 절약되는 햇빛 시간을 바로 증명하지 않는다. |
| 서울 사용자 유입 | 약함 | 스마트 발송을 아직 쓰지 않았고, 신규 사용자를 데려오는 경로가 없다. |
| 경로 결과 전환 | 측정 준비 중 | 로컬 변경에 `route_result_view`가 있으나 배포 반영을 확인해야 한다. |
| 재방문 이유 | 약함 | 최근 경로, 즐겨찾기, 다시 계산 기능이 없다. |
| 공유·확산성 | 약함 | 결과를 공유해 신규 사용자를 데려오는 기능이 없다. |
| 사용자 범위 | 제한적 | 서울 전역, 3km 이내 도보만 지원한다. |

현재 상태는 기술과 주제만 보면 수상권 후보다. 다만 1차 심사가 지표 종합 평가이므로 `서울 유입 → 결과 전환 → 재방문`을 함께 보강해야 한다. 공유는 유입 수단이지만 딥링크와 실기기 확인이 필요해 재방문 다음 순서로 둔다.

## 핵심 문제와 개선안

### 1. 결과의 가치를 사용자가 직접 계산해야 한다

현재 결과 화면은 빠른길, 균형, 그늘우선의 시간, 거리, 햇빛, 예상 그늘을 표로 보여준다. 정보는 충분하지만 사용자가 숫자를 직접 비교해야 한다.

결과 표 위에 다음 형식의 문장을 크게 표시한다.

> 그늘우선은 빠른길보다 2분 더 걸리고, 예상 햇빛 노출은 8분 적어요.

숫자는 선택한 경로와 빠른길의 계산 결과에서 만들고, 바로 아래에 다음 안내를 표시한다.

> 건물 데이터와 출발 시각을 기준으로 계산한 예상치예요.

선택 상태와 반올림 결과에 따라 문구를 분기한다.

| 상황 | 처리 |
| --- | --- |
| 선택한 경로가 빠른길 | 비교 문장 대신 `예상 햇빛 노출 15분`처럼 절대값을 표시한다. |
| 예상 햇빛 절약이 0분 이하 | 비교 문장을 숨기거나 과장 없는 중립 문구를 표시한다. |
| 예상 시간 차이가 0분 | `더 걸리지 않고`라고 표시한다. |
| 예상 햇빛 절약이 양수이고 시간 차이도 양수 | 시간 차이와 예상 햇빛 노출 차이를 함께 표시한다. |

`sunMinutes`는 분 단위로 반올림하므로 1분 미만의 차이가 0분이 될 수 있다. 짧은 경로에서도 자연스러운 문장이 나오도록 반올림 후의 값을 기준으로 위 분기를 적용한다.

이 문장은 그늘길의 기술을 사용자가 체감하는 가치로 바꾼다. 결과 공유 문구에도 같은 형식을 재사용할 수 있다.

### 2. 대표 전환을 실제 배포 데이터로 측정해야 한다

현재 로컬 코드에는 경로 계산 성공 후 `route_result_view`를 기록하는 변경이 있다.

- 대표 전환: `route_result_view`
- 보조 전환 후보: `route_search_submit`
- 보조 전환 후보: 경로 모드 선택 또는 결과 공유
- 진단 이벤트: `route_search_error`

오류 이벤트에는 검색어, 장소명, 좌표를 넣지 않는다. `near-goal`, `too-long`, `outside-seoul`, `complex-data`, `off-network`, `generic`처럼 제한된 오류 코드만 기록한다.

배포 후 콘솔의 `분석 > 이벤트`에서 이벤트 수집을 확인하고, `핵심 지표`에서 `route_result_view`를 대표 전환으로 설정한다. 토스 안내에 따르면 지표 변경은 다음 날부터 적용된다.

- [핵심 지표 기능 공식 안내](https://techchat-apps-in-toss.toss.im/t/topic/4086)
- [핵심 지표 개발자 가이드](https://developers-apps-in-toss.toss.im/analytics/conversion-metrics.html)
- [이벤트 로깅 가이드](https://developers-apps-in-toss.toss.im/analytics/logging.html)

### 3. 자연스러운 재방문 장치가 없다

첫 화면에 최근 경로를 다시 계산하는 버튼을 추가한다.

> 최근 경로  
> 강남역 11번 출구 → 역삼역  
> 지금 그늘로 다시 계산

최근 경로는 기기 내부에만 저장하되 사용자 위치 좌표와 검색어 원문은 저장하지 않는다. 이름으로 검색해 선택한 출발지와 도착지는 공개 장소 ID만 저장한다. 현재 위치를 출발지나 도착지로 사용한 경로는 챌린지 기간의 최근 경로 기능에서 제외한다. 앱을 다시 열면 저장된 장소 ID를 사용해 현재 시각의 그림자로 다시 계산한다. 시간에 따라 결과가 달라지는 그늘길의 특성과 잘 맞고, 로그인이나 서버가 필요 없다.

후보 기능의 우선순위는 다음과 같다.

1. 최근 경로 한 개 다시 계산
2. 최근 경로 여러 개 표시
3. 즐겨찾는 경로 저장

챌린지 기간에는 첫 번째 기능만 구현해도 충분하다.

### 4. 결과가 신규 사용자를 데려오지 못한다

결과 화면에 공유 버튼을 추가한다.

> 강남역→역삼역  
> 빠른길보다 예상 햇빛 노출이 8분 적은 길 보기

공유 링크를 누르면 토스에서 그늘길이 열리고, 가능하면 같은 출발지와 도착지가 선택된 상태로 시작한다.

개인정보 보호를 위해 다음 원칙을 지킨다.

- 현재 위치 좌표를 링크에 포함하지 않는다.
- 검색어 원문을 분석 이벤트에 포함하지 않는다.
- 공개 장소 ID로 만든 경로만 바로 공유한다.
- 현재 위치에서 시작한 경로는 일반 앱 공유 링크만 제공한다.

### 5. 서울 밖 사용자가 위치 오류만 보고 나갈 수 있다

서울 밖에서도 기본 예시 경로를 실행할 수 있다는 점을 더 분명히 보여준다. 기본으로 설정된 `강남역 11번 출구 → 역삼역` 경로를 이용한다.

첫 방문자에게 다음 버튼 문구를 검토한다.

> 예시로 그늘길 먼저 보기

예시 결과를 본 뒤 `내 경로 찾아보기`로 장소 검색을 유도한다. 서울 밖 사용자가 현재 위치 기능은 쓰지 못하더라도 앱의 핵심 가치는 경험할 수 있다.

스마트 발송은 서울 사용자만 대상으로 유지하는 것이 목표다. 다만 다음 제약은 콘솔에서 먼저 확인해야 한다.

- 8월 1일부터 26일까지 사용할 수 있는 발송 횟수와 주기
- 앱 홈만 가능한지, 특정 딥링크를 랜딩 경로로 지정할 수 있는지
- 실제로 서울 사용자 세그먼트를 선택할 수 있는지, 기존 사용자 전체만 가능한지

이 세 항목을 확인하기 전에는 `코드 변경 없이 서울 사용자에게 발송할 수 있다`고 가정하지 않는다. 딥링크 구현이 필요하거나 서울 타기팅을 지원하지 않으면 P0의 순서와 발송 문구를 다시 조정한다. 콘솔 확인은 출시 번들 준비와 병렬로 진행한다.

## 실행 우선순위

### P0 — 즉시

1. 출시 번들 준비와 병렬로 스마트 발송의 횟수·주기, 랜딩 경로, 타기팅 조건을 콘솔에서 확인한다.
2. 결과 요약 문장과 `route_result_view`를 현재 준비 중인 출시 수정사항에 포함해 하나의 출시 후보로 고정한다. 두 기능을 따로 배포하지 않는다.
3. 현재 워킹 트리의 앱 아이콘, 위치 처리, 경로 다시 보기, 서울 밖 안내, 분석 계측을 포함한 모든 변경에 다음 검증을 실행한다.

```bash
npm run data:verify && npm run test:coverage && npm run typecheck && npm run lint && npm run build
```

4. 위 명령은 헤드리스 검증이므로 화면 회귀를 잡지 못한다. 이번 번들은 결과 시트 레이아웃을 두 군데 바꾸므로 다음을 사람이 직접 확인한다.

   - 결과 요약 문장이 지표 표 위에 새로 들어가 시트 상단 높이와 핸들을 내렸을 때 남는 peek 영역이 밀린다.
   - `경로 다시 보기` 버튼이 지도 좌측 상단 컨트롤 열에 추가되어 좁은 폭에서 줄바꿈이 날 수 있다.

   확인 항목은 다음과 같다.

   - 320px와 390px 폭에서 검색 → 결과 → 시트 접기·펼치기가 넘침 없이 동작한다.
   - 앱인토스 샌드박스 실기기에서 결과 화면이 뜨고 경로 계산이 끝난다. module Worker와 Web Crypto 호환성은 아직 실기기에서 확인되지 않은 항목이다.

5. 헤드리스 검증과 화면 확인을 모두 통과해야만 한 번 배포한다. 하나라도 실패하면 배포를 멈추고 해당 회귀를 먼저 해결한다.
6. 라이브 환경에서 `route_result_view` 수집을 확인한 뒤 대표 전환 지표로 설정한다. 지표 변경은 다음 날부터 적용되는 점을 일정에 반영한다.
7. 콘솔에서 확인한 제약 안에서 스마트 발송 시점과 문구를 확정한다. 딥링크 코드가 추가되면 전체 검증부터 다시 통과한다.

### P1 — 다음 업데이트

1. 공개 장소 ID만 사용하는 최근 경로 저장을 추가한다. 현재 위치 기반 경로는 저장하지 않는다.
2. 첫 화면에 `지금 그늘로 다시 계산` 버튼을 추가한다.
3. 결과 공유 카드와 앱인토스 공유 링크를 추가한다.
4. 검색 시작, 성공, 실패, 모드 선택 퍼널을 기록한다.
5. 기본 예시 경로임을 첫 화면에서 더 명확히 안내한다.

### P2 — 지표 확인 후

1. 보조 전환 지표로 결과 공유나 경로 모드 선택을 검토한다.
2. 오류 유형별 발생 비율을 보고 검색·경로 성공률을 개선한다.
3. 최근 경로 여러 개 또는 즐겨찾기 확장은 실제 재방문 지표가 오른 뒤 검토한다.

## 판단 기준

업데이트 후에는 `서울 유입 → 결과 전환 → 재방문` 순서로 지표를 확인한다.

1. 스마트 발송과 공유 링크를 통한 서울 사용자 유입 수
2. 앱 방문자 중 `route_result_view`를 발생시킨 사용자 비율
3. 경로 검색 실패율과 오류 코드 분포
4. 다음 날 또는 며칠 안에 다시 방문한 사용자 비율
5. 최근 경로 다시 계산 사용률
6. 결과 공유 사용자 수와 공유 링크 유입 수

기능을 추가했는데 결과 전환율이나 재방문율이 오르지 않으면 기능을 더 붙이지 않는다. 이탈 구간과 실패 원인을 먼저 고친다.

## 최종 판단

그늘길은 기술을 더 복잡하게 만들 필요가 없다. 수상 가능성을 높이려면 이미 구현한 기술의 효과를 한 문장으로 증명하고, 사용자가 결과까지 도달하게 만들고, 같은 경로를 다시 찾게 해야 한다.

챌린지 기간의 제품 목표는 다음 문장으로 정리한다.

> 더 많은 사용자가 햇빛을 덜 받는 경로를 한 번에 확인하고, 필요할 때 다시 찾게 만든다.
